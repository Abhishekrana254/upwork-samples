A contractor types a trade, a quantity, and a unit cost. The app prices the line, rolls it into the job total, and keeps the last accepted number so a later edit does not silently replace a signed estimate.

Files

lines.py holds the math. store.py writes the accepted total. The page only displays what those two return. The pricing rule does not live in the button handler.

Architecture

Browser form, then a small API, then the pricing function, then a table of accepted estimates. A new draft can change. An accepted row changes only when someone accepts again, and the old total stays in history.

def price_line(qty, unit_cost, waste=0.0):
    qty = Decimal(str(qty))
    unit = Decimal(str(unit_cost))
    extra = qty * (Decimal(str(waste)) / Decimal("100"))
    return (qty + extra) * unit

def job_total(lines):
    return sum((price_line(l["qty"], l["unit_cost"], l.get("waste", 0)) for l in lines), Decimal("0"))

Waste is a percent on the quantity, applied before the unit cost. The total is a sum of money, not a float added in the page.
