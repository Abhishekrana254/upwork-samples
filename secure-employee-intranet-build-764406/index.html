Employee intranet with expiry

Abhishek Rana. A sketch of how the build would go.

The problem

The portal should follow the layout of a reference site that will be shared in private. Only employees get in. Each user the admin creates has an expiry date, and once that date has passed the account locks on its own. The admin screen adds, edits, and bulk-imports users, sets expiry, and shows activity. Login is token-based, with password reset, and SSO only if it shortens the first release. Staff need a way to message each other. The hand-off is a responsive front end, a backend with roles and expiry, the admin screen, the messaging piece, a deploy script, and a short setup note for the owner's server. An expired account cannot log in until someone reactivates it. A new user should be addable in under a minute. Pages should load in under two seconds on ordinary broadband.

Flow

  1. Match the reference layout in the web app after the private link is shared.
  2. Create a user with an expiry date from the admin screen or a bulk file.
  3. On every login, reject the token if the expiry date is already past or the account is locked.
  4. Let an admin set a new expiry to turn the account back on.
  5. Add staff messages on the same session, then ship the deploy script and the setup note.

Files

  • api/auth.py issues the token and runs the expiry check on each request.
  • api/users.py creates, edits, and bulk-imports users, and writes the activity row.
  • api/messages.py stores a staff message for the signed-in user only.
  • web/src/AdminUsers.jsx is the React form for one user or a CSV import.
  • web/src/Messages.jsx is the message list, usable on a narrow screen.
  • deploy.sh and README.md are the server launch steps.

Architecture

React talks to a FastAPI backend. The admin creates a user with a status and an expiry stored as a date. Login checks that pair before a token is accepted. If today is after the expiry date, the result is expired and no token is issued. A locked status stays blocked even when the date is still ahead, so reactivation is a deliberate admin edit, not a clock reset. Bulk import drops a row that has no email or no full date. Staff messages use the same token. The reference layout is applied in the React pages once that site is shared. This is a sketch of the gate. It is not a claim that the portal is already online.

Lock when the date has passed

def can_login(user, today):
    if user["status"] == "locked":
        return False, "locked"
    if today > user["expiry"]:
        return False, "expired"
    return True, "ok"

def import_row(row):
    email = row.get("email", "").strip().lower()
    expiry = row.get("expiry", "").strip()
    if "@" not in email or len(expiry) != 10:
        return None
    return {"email": email, "expiry": expiry, "status": "active"}

On 2026-10-13, an active user whose expiry is 2026-10-12 is expired. The same day is still allowed when expiry is 2026-10-13. A locked user with expiry 2026-12-01 stays locked. Setting status back to active and expiry to 2026-11-01 lets them in again. A bulk row " A@B.com " with expiry 2026-12-01 becomes a@b.com and active. A row with no @ or a blank date is skipped.
