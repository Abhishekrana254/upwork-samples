Private codebase vetting

Abhishek Rana. A sketch of how the build would go.

The problem

An AI training pipeline needs real production repositories, not toy demos, across stacks such as Python, Rust, C++, TypeScript, Go, and Java. Each repository has to come with a non-exclusive license from the original copyright holder, a Git history that is actually theirs, tests, documentation, and a build that runs. Before any contract starts, 2 to 3 anonymized sample packs have to pass a quality and rights review. After that, batches must be secret-scrubbed and still include tests, docs, and commit logs. No milestone is paid until those first packs are approved.

Flow

  1. Record the copyright holder and a signed non-exclusive license before any files are copied.
  2. Count commits, test files, and whether a build command is recorded.
  3. Scan the tree for keys and tokens, then replace each hit.
  4. Build an anonymized sample pack and stop until that pack is approved.
  5. Deliver the scrubbed batch with tests, docs, commit logs, and the rights note.

Files

  • vet.py rejects a repo with a short history, no signed rights flag, too few tests, no build note, or a secret still in the tree.
  • pack.py writes the anonymized review copy after scrubbing, without removing the rights note.
  • manifest.csv lists a repo id, language, commit count, test count, and accept or the reject reasons.
  • rights_note.md stores who signed, and that the license is non-exclusive. It stays outside the training files.
  • README.md states that a batch is not sent until the sample pack is approved.

Architecture

The check is a Python gate in front of any delivery. A repository is accepted only when the history is deep enough, tests and a build note are present, the rights flag is signed, and a second scan finds no secrets. Scrubbing replaces a hit with a marker. The sample pack is a review copy with secrets and contact lines removed. The rights note is kept beside the pack so the owner is not erased. This page is that gate. It is not a licensed repository and it is not a batch ready for training.

Accept or reject one repo

import re

SECRET_PATTERNS = [
    ("aws_access_key", re.compile(r"AKIA[0-9A-Z]{16}")),
    ("assigned_secret", re.compile(r"(?i)(?:api[_-]?key|secret|token)\s*[:=]\s*['\"][^'\"]{12,}['\"]")),
    ("private_key", re.compile(r"-----BEGIN (?:RSA |OPENSSH |EC )?PRIVATE KEY-----")),
]

def find_secrets(text):
    return [name for name, pat in SECRET_PATTERNS if pat.search(text)]

def scrub(text):
    out = text
    for name, pat in SECRET_PATTERNS:
        out = pat.sub("[REDACTED:" + name + "]", out)
    return out

def vet_repo(meta, files, min_commits=20, min_tests=1):
    reasons = []
    if meta.get("commits", 0) < min_commits:
        reasons.append("shallow_history")
    if not meta.get("rights_signed"):
        reasons.append("rights")
    if meta.get("test_files", 0) < min_tests:
        reasons.append("tests")
    if not meta.get("build"):
        reasons.append("build")
    secret_hits = []
    for path, text in files.items():
        for name in find_secrets(text):
            secret_hits.append(path + ":" + name)
    if secret_hits:
        reasons.append("secrets")
    return {"accept": not reasons, "reasons": reasons, "secrets": secret_hits}

A repo with 40 commits, a signed rights flag, 3 test files, and a build note is accepted when the source is clean. Four commits returns shallow_history. A missing signature returns rights. A file that contains an AKIA key and an assigned api_key is rejected for secrets, and scrub replaces both hits so a second scan is empty. A line that begins a private key is flagged the same way.
