Numeric preprocessing for ML

Abhishek Rana. A sketch of how the build would go.

The problem

Large numeric CSVs are messy and need to be ready for model training. The pipeline has to be reproducible: audit the raw files, handle missing values and extremes, scale or normalize where it matters, build useful features, and write train, validation, and test sets. Python with pandas, NumPy, and scikit-learn is the default. The same steps must run inside a Docker image that CI can start with one command. The hand-off is cleaned CSV or Parquet, versioned scripts, a Dockerfile, a short README, and a report of decisions, assumptions, and what to do next.

Flow

  1. Audit each raw CSV: row count, missing cells, and the spread of each numeric column.
  2. Split into train, validation, and test before any fill or scale is fit.
  3. Fit median, clip bounds, and scale on the training rows only.
  4. Apply that fit to validation and test, and add the agreed features.
  5. Write the three sets and a short report, then run the same script from Docker.

Files

  • audit.py prints missing counts and simple spread for each numeric column. It does not change the file.
  • preprocess.py splits the rows, fits on train, applies the fit, and adds features.
  • Dockerfile installs pandas, NumPy, and scikit-learn and runs preprocess.py.
  • README.md is the one-command reproduction note for CI.
  • report.md records each decision, the assumption behind it, and the next step.
  • out/train.parquet, out/val.parquet, and out/test.parquet are the sets the model code should read.

Architecture

The split happens first so later rows cannot leak into the fit. Medians, clip bounds, and the scale are computed on the training split only, then applied to validation and test. A missing amount is filled with the training median. A value outside the training clip bounds is pulled back to that bound before scaling. A ratio feature uses the filled raw numbers, not the scaled ones. Docker runs that same script so CI rebuilds the three files from the raw CSV. The report states what was assumed. This is a sketch of that pipeline. It is not a claim that these datasets have already been cleaned.

Fit on train, apply after

def fit_columns(rows, features):
    stats = {}
    for name in features:
        values = sorted(row[name] for row in rows if row[name] is not None)
        if not values:
            raise ValueError("empty column " + name)
        n = len(values)
        median = values[n // 2]
        q1 = values[n // 4]
        q3 = values[(3 * n) // 4]
        iqr = q3 - q1
        mean = sum(values) / n
        var = sum((value - mean) ** 2 for value in values) / n
        std = var ** 0.5 or 1.0
        stats[name] = {
            "median": median,
            "lo": q1 - 1.5 * iqr,
            "hi": q3 + 1.5 * iqr,
            "mean": mean,
            "std": std,
        }
    return stats

def apply_row(row, stats, features):
    clean = {}
    for name in features:
        spec = stats[name]
        value = row[name] if row[name] is not None else spec["median"]
        if value < spec["lo"]:
            value = spec["lo"]
        elif value > spec["hi"]:
            value = spec["hi"]
        clean[name] = (value - spec["mean"]) / spec["std"]
    amount = row["amount"] if row["amount"] is not None else stats["amount"]["median"]
    units = row["units"] if row["units"] is not None else stats["units"]["median"]
    clean["ratio"] = amount / units
    return clean

On training amounts 10, 20, 30, 40, and 50, the median is 30 and the high clip is 70. A missing amount becomes that median, then scaled. An amount of 1000 is clipped to 70 before scaling, so it does not dominate the column. The ratio for a missing amount and 4 units is 30 / 4. A 10-row split with fractions 0.6 and 0.2 yields 6, 2, and 2 rows, and the same seed repeats the same split.
