Voice agent turn loop

Abhishek Rana. Python services in production, including work at Microsoft.

A caller speaks. Speech becomes text. The agent answers from the allowed tools only, then the reply is spoken back. If the caller talks over the reply, the current audio stops and the new turn starts.

1. Audio in2. Transcript3. Tool call4. Spoken reply5. Barge-in cuts audio

Files

session.py owns one call. tools.py is the only place a tool can run. The model does not get a free-form shell. Each turn stores the transcript, the tool name, and the audio id, so a bad call can be replayed.

Architecture

Telephony webhook to a session service. The session calls speech-to-text, then the model with a fixed tool list, then text-to-speech. Barge-in is a flag on the session: new speech sets it, and the player checks it before the next audio chunk.

def on_caller_speech(session, transcript):
    session.barge_in = True
    session.stop_audio()
    tool, args = pick_tool(transcript, session.allowed_tools)
    result = run_tool(tool, args)
    reply = speak(result)
    session.turns.append({"heard": transcript, "tool": tool, "audio": reply})
    return reply

The allowed tool list is the boundary. A transcript that does not match a tool gets a short spoken fallback, not a guessed action.
