A page saves the desired state. A worker reads that state and applies it to the cluster. If the apply fails, the record stays dirty and the next pass retries. A deploy rolls the deployment from CI, not from the page.

1. Desired state saved2. Worker reads it3. Apply to cluster4. Fail stays dirty5. CI rolls the deploy

Files

The API stores desired state only. Worker is the only process that talks to the cluster. The page never holds a kube credential. CI owns the rollout.

Architecture

TypeScript page, .NET API, a worker loop, Kubernetes. Desired and actual are separate rows. The reconcile step compares them. Equal means clean. Not equal means apply, then write the result.

app.MapPost("/desired", async (Desired body, Db db) =>
{
    var row = await db.States.FindAsync(body.Name) ?? new State { Name = body.Name };
    row.Spec = body.Spec;
    row.Dirty = true;
    db.Update(row);
    await db.SaveChangesAsync();
    return Results.Ok(new { row.Name, row.Dirty });
});

Setting Dirty is the signal. The worker clears it only after the cluster matches Spec.
