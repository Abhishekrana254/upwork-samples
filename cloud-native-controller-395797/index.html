Hybrid cloud controller Desired state in, a worker reconciles, the UI only shows what the cluster already did.

Flow

  1. TypeScript page posts the desired service: image, replicas, region.
  2. .NET API checks the body and writes one row. It does not talk to the cluster on the request thread.
  3. A worker pod reads that row, applies it with the Kubernetes client, and writes the observed status back.
  4. If the apply fails, the row stays dirty and the next pass retries. The API does not hide the failure.
  5. CI builds the image, pushes it, and rolls the deployment. The page reads status. It does not SSH.

What the page is

A sample of the shape. Not a client system, and not a number from a past incident.

Docker for the API and the worker. Kubernetes for the reconcile loop. The front end only renders the status the worker stored.

Controller sample

record Desired(string Name, string Image, int Replicas);

app.MapPost("/services", (Desired body, Store store) =>
{
    if (string.IsNullOrWhiteSpace(body.Image) || body.Replicas < 1)
        return Results.BadRequest(new { error = "image and replicas are required" });
    var id = store.Enqueue(body);
    return Results.Accepted($"/services/{id}", new { id, status = "pending" });
});

// Worker, separate process. The request above already returned.
async Task Reconcile(Store store, IKube kube, CancellationToken stop)
{
    var job = store.NextDirty();
    if (job is null) return;
    try
    {
        await kube.ApplyAsync(job.Desired, stop);
        store.Mark(job.Id, "ready");
    }
    catch (Exception ex)
    {
        store.Mark(job.Id, "dirty", ex.Message);
    }
}
