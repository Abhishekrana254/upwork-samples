Web and Android chatbot

Abhishek Rana. A sketch of how the build would go.

The problem

The product vision is already set: an AI chatbot in the browser and as an Android app. What is missing is the path from that vision to something people can use. That means a database, server logic, model integration, and both interfaces talking to the same place. The NLP side has to choose or fine-tune a model, run inference, and expose a clean endpoint. The web client can be React or Vue. The Android app can be Kotlin, Flutter, or React Native. Both must share the backend and the database. The hand-off is a deployed backend with authentication, chat history, and the NLP service, a responsive web UI, an Android build on an internal test track, short docs, and a session so the owner can maintain the code.

Flow

  1. Create accounts and store each chat turn against the signed-in user.
  2. Build the model request from that user's recent turns plus the notes that may answer the question.
  3. Return the reply and save it, so the next turn still has the thread.
  4. Point the web client and the Android app at the same endpoint.
  5. Publish the Android build to an internal track and walk through the repo.

Files

  • api/auth.py checks the session before any history is read.
  • api/chat.py appends a turn, keeps only that user's rows, and builds the model messages.
  • api/store.py writes chat history. Another user's rows are never returned.
  • web/src/Chat.jsx is the React screen. It posts the message and renders the thread.
  • android/app/src/main/java/chat/ChatScreen.kt is the Kotlin screen. It calls the same route.
  • README.md covers run, auth, where history lives, and how the internal Android track is published.

Architecture

One FastAPI service sits between both clients and the model. The web app and the Android app send the new message and a session. The service loads only that user's recent turns, adds a short system line and any notes, and asks the model. The reply is stored before it is sent back, so a later message on the other device still sees the thread. Empty text is rejected. A turn from a different account is not copied into the prompt. This is a sketch of that shared core. It is not a claim that the app is already in a store or a browser.

One prompt for both clients

def append_turn(history, user_id, role, text):
    if role not in ("user", "assistant"):
        raise ValueError("role")
    cleaned = text.strip()
    if not cleaned:
        raise ValueError("empty")
    return history + [{"user_id": user_id, "role": role, "text": cleaned}]

def history_for(history, user_id, limit=6):
    rows = [row for row in history if row["user_id"] == user_id]
    return rows[-limit:]

def model_messages(history, user_id, query, notes):
    messages = [{
        "role": "system",
        "text": "Answer from the notes. If the notes do not cover it, say so.",
    }]
    for row in history_for(history, user_id):
        messages.append({"role": row["role"], "text": row["text"]})
    body = "Notes:\n" + "\n".join(notes) + "\n\nQuestion: " + query.strip()
    messages.append({"role": "user", "text": body})
    return messages

A user asks "Where is my order?" and the assistant says "It ships Friday." A second account's line, "Secret other user", is not in the next prompt. The new question is "Can I change it?" and the note "Orders can be changed before Thursday." is included. Blank text is rejected. Only the last six turns for that user are kept.
