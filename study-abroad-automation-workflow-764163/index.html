Study abroad lead workflow

Abhishek Rana. A sketch of how the build would go.

The problem

Study abroad consultancies need one working MVP that can later be copied for more than one client. A lead comes in from one source, such as Meta Lead Ads or a website form, and lands in Google Sheets or a database. Rules that the consultancy can change decide if the student is qualified. WhatsApp Business API sends the reply. A counselor is assigned and notified. Consultation booking and reminders run on their own. A basic dashboard shows where each lead stands. Duplicates are blocked, errors are caught, and a person takes over when the automation should stop. The posted budget is Rs 15,000 to Rs 35,000, and the posted window is about 2 to 3 weeks once the integrations are approved.

Flow

  1. Receive the lead on an n8n webhook from Meta Lead Ads or the form.
  2. Normalise the phone and skip the row if that phone is already stored.
  3. Apply the qualification rules, or hand the lead to a person when a required field is missing.
  4. Assign the counselor with the fewest open leads and send the WhatsApp notice.
  5. Book the consultation, send reminders, and show the same rows on a simple dashboard.

Files

  • lead_intake.workflow.json is the n8n webhook that accepts Meta Lead Ads or the form and writes the sheet.
  • qualify_assign.workflow.json calls the rules, assigns a counselor, and sends WhatsApp.
  • booking_reminders.workflow.json books the consultation and sends the reminder.
  • rules.py normalises the phone, blocks duplicates, qualifies, and picks the counselor.
  • dashboard.html reads the sheet and shows status, counselor, and next reminder.
  • README.md covers deploy, the error path, and the third-party tools with their recurring costs.

Architecture

n8n is the runner. The webhook receives one lead, rules.py decides duplicate, handoff, nurture, or qualified, and n8n writes that result to Google Sheets. Qualified rows trigger a WhatsApp Business API message and a counselor notification. A second workflow handles booking and reminders. If a call fails, the row is marked for a person instead of being dropped. The dashboard only reads the sheet. Each consultancy gets its own rule set and counselor list, so the same workflows can be copied later. The sketch does not assume Meta, WhatsApp, or the sheet are already connected.

Routing one lead

def phone_key(raw):
    digits = "".join(ch for ch in str(raw) if ch.isdigit())
    if len(digits) == 12 and digits.startswith("91"):
        digits = digits[2:]
    if len(digits) == 11 and digits.startswith("0"):
        digits = digits[1:]
    return digits

def route_lead(lead, seen, rules, counselors, open_counts):
    phone = phone_key(lead.get("phone", ""))
    if len(phone) != 10:
        return {"action": "handoff", "reason": "phone", "phone": phone}
    if phone in seen:
        return {"action": "duplicate", "phone": phone}
    if lead.get("ielts") is None or lead.get("country") is None or lead.get("intake") is None:
        return {"action": "handoff", "reason": "missing field", "phone": phone}
    qualified = (
        lead["country"] in rules["countries"]
        and lead["ielts"] >= rules["min_ielts"]
        and lead["intake"] in rules["intakes"]
    )
    if not qualified:
        return {"action": "nurture", "phone": phone}
    counselor = min(counselors, key=lambda name: (open_counts.get(name, 0), name))
    return {"action": "qualified", "phone": phone, "counselor": counselor}

With countries Canada and UK, minimum IELTS 6.0, and intakes Sep and Jan, a UK lead at IELTS 6.5 for Jan with phone 09844444444 becomes qualified for Rohit when Rohit has fewer open leads than Asha. The same phone written as +91 98111 11111 is a duplicate. IELTS 5.5 is nurture. A short or missing phone is a handoff.
