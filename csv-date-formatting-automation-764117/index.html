CSV Date Formatting Automation

Abhishek Rana. A sketch of how this build would go.

The problem

CSVs are supposed to arrive with dates already in DD/MM/YYYY, but cells often show up as D/M/YY or YYYY-MM-DD. Those files then go into a reporting workflow. The tool should take one uploaded CSV, scan every column or only the columns that are flagged, turn cells that are clearly dates into DD/MM/YYYY, and hand back a downloadable CSV. Non-date fields stay as they are. Row count stays the same. It runs locally on Windows or macOS. Python and pandas are the preferred stack so the script can be extended later.

Flow

  1. Pass a CSV path, or pick the file in a small local window.
  2. Read it with pandas and keep the original column order.
  3. Walk every cell, or only the flagged columns.
  4. If the text matches a known date pattern, write it back as DD/MM/YYYY. Otherwise leave the cell alone.
  5. Save a new CSV with the same number of rows.
  6. Keep a short before-and-after sample next to the README.

Files

  • normalise.py holds the date patterns and the cell converter. It does not read a file.
  • cli.py is the command-line entry. It takes the input path, an optional column list, and the output path.
  • app.py is a tiny local page: upload a CSV, download the cleaned one. Same function as the CLI.
  • README.md covers setup on Windows and macOS and one example command.
  • samples/before.csv and samples/after.csv show D/M/YY and YYYY-MM-DD turned into DD/MM/YYYY, with names and amounts unchanged.

Architecture

One function decides if a cell is a date. The CLI and the upload page both call that function, so the rules live in a single place. Pandas reads and writes the table. A cell that matches none of the patterns is returned unchanged, which is what keeps amounts, ids, and notes intact. The output file is a new path. The input file is not overwritten. This page is only the shape of that tool. It does not assume a reporting system is already wired up.

Core step

from datetime import datetime

FORMATS = (
    "%Y-%m-%d",
    "%d/%m/%Y",
    "%d/%m/%y",
    "%d-%m-%Y",
    "%d-%m-%y",
    "%Y/%m/%d",
)

def normalise_cell(value):
    """Return DD/MM/YYYY when the cell is a known date, else the original value."""
    if value is None:
        return value
    text = str(value).strip()
    if not text or text.lower() == "nan":
        return value
    for fmt in FORMATS:
        try:
            parsed = datetime.strptime(text, fmt)
        except ValueError:
            continue
        return parsed.strftime("%d/%m/%Y")
    return value

def normalise_frame(frame, columns=None):
    """Copy the table. Convert flagged columns, or every column when columns is None."""
    out = frame.copy()
    targets = list(columns) if columns else list(out.columns)
    for name in targets:
        out[name] = out[name].map(normalise_cell)
    if len(out) != len(frame):
        raise RuntimeError("row count changed")
    return out

Questions to settle first

  1. Should every column be scanned, or only a list of date columns you name?
  2. For a two-digit year such as 25 in D/M/YY, is 2025 the right century?
  3. If a cell looks like a date but is impossible, such as 31/02/2024, should it stay unchanged or be reported?
