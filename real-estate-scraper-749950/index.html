Listing scraper

Abhishek Rana. Python data jobs in production, including work at Microsoft.

A listing page is fetched, parsed into fields, and written once per listing id. The next run updates price and status on that same id. It does not insert a second row because the photo order changed.

1. Fetch2. Parse fields3. Key on listing id4. Upsert5. Failures logged, run continues

Files

fetch.py gets the page. parse.py returns address, price, beds, and status, or an error. store.py upserts on listing id. A parse error is a row in the failure log, not a crash of the batch.

Architecture

One worker, one site adapter. The adapter is the only file that knows the page shape. Storage and the schedule do not. A second site is a second adapter with the same return shape.

def upsert(conn, listing):
    conn.execute(
        """
        INSERT INTO listings (id, address, price, beds, status)
        VALUES (?, ?, ?, ?, ?)
        ON CONFLICT(id) DO UPDATE SET
          price=excluded.price,
          status=excluded.status
        """,
        (listing["id"], listing["address"], listing["price"], listing["beds"], listing["status"]),
    )

The conflict key is the listing id from the source, not the row number from this run.
