A text arrives. The same provider message id is stored once. STOP, UNSUBSCRIBE, CANCEL, END, and QUIT opt the number out before any other reply. A later text from that number does not start a new job.

1. Webhook2. Dedup on message id3. STOP check4. Parse the ask5. One reply

Files

webhook.py reads the provider payload. optout.py owns the stop words and the opted-out set. jobs.py creates the work item only after the stop check passes. The reply text is not assembled inside the HTTP handler.

Architecture

Provider posts to one endpoint. The handler writes the raw message, then calls opt-out, then either stops or opens a job. SPF, DKIM, and DMARC sit on the mail side of the same intake when the channel is email. SMS uses the provider signature instead.

STOP = {"stop", "unsubscribe", "cancel", "end", "quit"}

def intake(message_id, from_number, body, seen, opted_out):
    if message_id in seen:
        return "duplicate"
    seen.add(message_id)
    if body.strip().lower() in STOP:
        opted_out.add(from_number)
        return "opted_out"
    if from_number in opted_out:
        return "blocked"
    return "job"

Order matters. Dedup first, then STOP, then the old opt-out, then a job. Reversing that sends a reply to someone who already stopped.
