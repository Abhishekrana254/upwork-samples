intake.py writes one row per client request. retrieve.py picks the passages. worker.py is the only file that calls the model. page.js renders the answer and never holds a secret. A .NET service on the other side of the API stays behind that same row.

Architecture

The row is the contract. Retrieval reads the client's documents for that row only. The model does not answer from an empty context. A second client does not read the first client's row.

def answer(row, passages):
    question = str((row or {}).get("question") or "").strip()
    picked = [p for p in (passages or []) if p]
    if not question or not picked:
        return {"ok": False, "error": "need a question and a passage"}
    return {"ok": True, "question": question, "passages": picked, "state": "ready"}
